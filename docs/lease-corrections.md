## الواجهات الذرية

الملف: `client/src/lib/prototype-lease-lifecycle.ts`.

```ts
createLease(state, values: Record<string, string>): { state, result: DemoEntity }
activateLease(state, leaseId: string, asOf: string): { state, result: DemoEntity }
renewLease(state, leaseId: string, values: Record<string, string>): { state, result: DemoEntity }
terminateLease(state, leaseId: string, values: Record<string, string>): { state, result: DemoEntity }
refreshLeaseCalendar(state, asOf?: string): { state, result: number }
createLeaseVacancy(state, values: Record<string, string>): { state, result: DemoEntity }
endLeaseVacancy(state, vacancyId: string, values: Record<string, string>): { state, result: DemoEntity }
```

كل انتقال نقي ويعيد `{ state, result }`، ويستخدم من الواجهة عبر:

```ts
commitTransition(previous => createLease(previous, values))
```

### سلوك R09

- إنشاء يدوي يصنع عقدًا ومستأجرًا مرتبطًا بالعقار/المحفظة عند الحاجة، لكنه يبقى **مسودة**: لا إشغال ولا استحقاق ولا قبض.
- التفعيل الصريح يتحقق من دور الموظف، نطاق المحفظة، المستأجر، الإيجار الموجب، تواريخ ISO وترتيبها، والوحدة/العقار. ينشئ ذممًا شهرية مؤرخة بمفاتيح ثابتة `leaseId:YYYY-MM` وفق UTC، مرة واحدة فقط، ولا ينشئ أي `collections` أو نقد.
- الإشغال مشتق من تاريخ `asOf`: العقد المستقبلي لا يشغل الوحدة. زر «تحديث التقويم» صريح ولا توجد مهمة خلفية.
- يُرفض تداخل عقدين نافذين على الوحدة، كما يُعامل هدف `meta.wholeProperty === true` كنطاق العقار كله عند فحص التداخل.
- الإنهاء مؤرخ: لا يحذف العقد أو الذمم أو الإيصالات. يمكنه فقط وسم الذمم المستقبلية غير المدفوعة `ملغى` مع سبب الإنهاء؛ الذمة التي بها قبض/تحصيل جزئي تبقى دون إلغاء.
- التجديد ينشئ إصدار عقد جديدًا ذا `priorLeaseId` و`rootLeaseId` بدل ترقيع العقد السابق. ولا يُغلق السابق عند بداية الخلف إلا بتأكيد صريح.
- `requestId` مدعوم لإنشاء العقد، التجديد، الإنهاء، وإنشاء/إنهاء الشغور؛ إعادة الطلب المتطابق تعيد النتيجة الأصلية ولا تكرر الكتابة، والطلب نفسه ببيانات مختلفة يُرفض.

### سلوك R12

- سجل الشغور يأخذ `portfolioId` من العقار نفسه حتى عند اختيار «كل المحافظ»، ويتحقق من علاقة الوحدة بالعقار والمحفظة.
- إنشاء الشغور يرفض أي وحدة/نطاق عليه عقد نافذ فعليًا في تاريخ بداية الشغور؛ إضافة سجل الشغور وتحديث حالة الوحدة انتقال واحد ذري.
- إنهاء الشغور يحفظ تاريخه وملاحظته، ثم يضع الوحدة «مؤجرة» فقط إن وُجد عقد نافذ في **تاريخ الإنهاء**، وإلا فهي «شاغرة»؛ لا يُحذف سجل الشغور.
- `lostIncome` يمر عبر `toMinor` ويظل تقديرًا تشغيليًا فقط، لا إيرادًا أو ذمة أو قبضًا.
