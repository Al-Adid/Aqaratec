# رحلة قبول المرحلة الأولى P01–P11

## النطاق وطريقة التشغيل

هذا اختبار قبول مترابط ببيانات صورية محلية فقط. مصدره [`client/src/lib/phase1-journey.spec.ts`](../client/src/lib/phase1-journey.spec.ts)، ويبدأ في كل حالة من `emptyEntityMap` جديدة ثم ينفذ انتقالات النطاق الحقيقي. لا يعيد استعمال بيانات الديمو ولا يبني أرصدة أو حالات نجاح يدويًا.

يتكون الـfixture من محفظتين: «محفظة ألف» و«محفظة باء»، ثم ينشئ عبر `createRentalProperty` فيلا مؤجرة بالكامل بهدف تأجير داخلي واحد، وعمارة مقسمة إلى ثلاث وحدات `U-01` و`U-02` و`U-03`. ساعة السيناريو المعلنة هي `2026-10-24` وليست تاريخ تشغيل فعليًا.

شُغّل الأمر التالي بنجاح في 25 أكتوبر 2026:

```bash
pnpm vitest run client/src/lib/phase1-journey.spec.ts
```

النتيجة الفعلية: **ملف اختبار واحد ناجح؛ 11 حالة ناجحة و2 معلقتان صراحةً**. استغرق التشغيل 2.48 ثانية. لم يُشغّل في هذا العمل اختبار المتصفح أو قاعدة بيانات أو مزود أو نشر.

## حالات معلقة صراحةً

1. **P10b — دفع المصروف الصريح المنفصل:** لم تنفذ؛ لا توجد دالة انتقال عامة تدفع مصروف الصيانة. الاختبار لا ينشئ `Payment` ولا يحول حالة المصروف يدويًا لكي يوهم بنجاح غير موجود. الاختبار المتاح يثبت فقط أن الصيانة لا تنشئ الدفع تلقائيًا.
2. **P11b — تصدير واجهة المستخدم ثم استيراده إلى مساحة جديدة:** لم تنفذ؛ واجهة التصدير الحالية تعطي نصًا خامًا، ولا توجد واجهة استيراد/استعادة عامة تقبله. اختبار P11 هو استعادة غلاف التخزين الذري، وليس بديلاً عن رحلة التصدير والاستيراد.
