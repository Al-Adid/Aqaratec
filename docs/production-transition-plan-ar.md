# خطة انتقال صُنّاع الفرص من البروتوتايب إلى التشغيل الإنتاجي

**قرار التسليم الحالي:** نسخة تجريبية محلية ببيانات صورية، مع حفظ سحابي اختياري للقطة الحساب، لا نظام محاسبة إنتاجي. لم تُنفَّذ هذه الخطة، ولم يُنشر الإصلاح أو تُشغل هجرة SQL أو يُفعّل مزود جديد أو تُدخل بيانات فعلية.

## 1. نموذج البيانات وملكية الوصول

قبل التشغيل، ينقل المنتج من `DemoEntity.meta` ولقطة JSON إلى جداول واضحة: المؤسسة، العضوية، المحفظة، العقار، وحدة التأجير، الطرف، العقد وإصداره، قالب العقد وإصداره، الاستحقاق، الفاتورة وبنودها، الحركة المالية والتخصيص، الشيك وحالاته، المورد، أمر الشراء، مشروع التطوير، المهمة، المستند، مصدر البيانات، ومراجعة التوصية. يحتفظ المصدر بسجل منشأ وتاريخ نفاذ وعملة ومعرف غير قابل لإعادة الاستخدام.

العزل يُنفَّذ في الخادم وطبقة القراءة والكتابة لكل عملية ومؤسسة، لا من اختيار دور في واجهة المستخدم. أدوار معاينة الموظف والمالك الموجودة الآن تجربة واجهة وليست منظومة RBAC مؤسسية. تُحدَّد مصفوفة العرض والتحرير والاعتماد والتفويض المؤقت، مع تحقق مستقل للإجراءات الحساسة ومنع اعتماد صاحب الطلب لطلبه. يجب اختبار مؤسستين وحسابين بجلسات فعلية داخل بيئة اختبار منفصلة.

## 2. دفتر مالي وذمم وتخصيصات قابلة للتدقيق

يحتاج التشغيل دفترًا مزدوجًا ودليل حسابات وأبعاد المحفظة والعقار والوحدة والمالك والمشروع. تُثبت قواعد الاعتراف بالاستحقاق، والتخصيص الجزئي والدفعات المقدمة، والتأمين والاسترداد وخسارة عدم التحصيل ورد الشيك وأصل القرض وتكلفته. تنشأ التسويات والعكس بقيود مؤرخة مرتبطة بالأصل بدل تحرير حركة قديمة بلا أثر. المبالغ وحدات نقدية صحيحة/عشرية ثابتة مع تحقق من التجميع والعملات ومنع جمع عملات مختلفة بلا سياسة صرف ومصدر.

الفاتورة والمطالبة وأمر الشراء وسند القبض كيانات منفصلة؛ أمر الشراء لا يؤكد الاستلام أو الدفع. الأرقام المتسلسلة تُخصص في معاملة قاعدة بيانات لا اعتمادًا على آخر رقم في جهاز محلي. لقطة سند القبض التاريخية والأطراف والمبلغ والتخصيصات محفوظة غير قابلة للتحرير العادي. الإقفال الحقيقي يفرض حظرًا على كل مسارات الفترة مع استثناء تسوية مرخصة؛ علامة المتابعة في البروتوتايب ليست هذا الإقفال.

## 3. دورة العقد والعقار والمستند

تُعتمد قواعد التفعيل والتجديد والإنهاء وتواريخ النفاذ والتداخل، وآلية جدولة إنشاء الاستحقاقات بأسلوب idempotent ومعاملات ذرية. يُحسم تقسيط جزء الشهر وإشعارات الإنهاء وتعديل الأجرة والتأمين والعقد المستقبلي بحسب عقد وقانون مراجعين، لا باستنتاج آلي. التأجير الكامل والوحدات تنظيم داخل قاعدة البيانات، ولا يثبت ترخيص تقسيم أو تغيير استعمال.

القوالب المرفوعة حاليًا TXT/Word تُحوّل إلى نص للمراجعة ولا تحفظ تنسيق Word الأصلي أو توقيعًا. للإنتاج يُختار محرك قوالب يحفظ تنسيق المستند، واختبارات PDF/A4 عربية طويلة ومتعددة الصفحات، وتخزين خاص بإصدارات وفحص أمني وروابط مؤقتة. تُراجع الصياغة والتوقيع والتسجيل ومهلة الحفظ قانونيًا في السوق المستهدف. لا يثبت قالب مطبوع أو توقيع مصور تسجيلًا حكوميًا.

## 4. المستشار ومحرك القرار والبيانات السوقية

يبقى محرك الحسابات مستقلًا عن الشرح اللغوي، ويُنسَّخ مع كل خطة وتوقع. تُقاس جودة التغطية ومصادر وتواريخ البيانات، وتُفصل الملاحظة النقدية التاريخية عن الدخل المتكرر المستدام، وأثر المتأخرات والدفعات المجمعة والشغور والرأسمالي. تحتاج توقعات الثروة نموذج حركة أصول وديون وفائدة وأقساط وسحب ورسوم وضرائب مع سيناريو ومصدر وتاريخ لكل فرض.

قنّاص الفرص يحتاج موصلات مصرحًا بها وحقوق استخدام ومصادر قطرية محققة، وأعمال جلب مجدولة بميزانيات وحداثة ومنع تكرار وسجل إخفاقات. العثور على إعلان لا يعني تحقق الثمن أو العائد أو التمويل أو قانونية التطوير. يمر الترشيح بفحص ملاءمة اقتصادي خاص بالهدف وملاءمة تمويل مؤكدة ثم فحص المستند والدليل. التمويل المحتمل لا يصبح موافقة، ولا تُنفذ صفقات أو قروض أو مشاركة مستندات آليًا.

## 5. الحفظ والتزامن والتعافي

حفظ JSON لكل مستخدم مع CAS الآن يحمي اللقطة التجريبية، لكنه ليس مساحة فريق أو دفتر متعدد المستخدمين. التشغيل يحتاج معاملات على الكيانات، وسجل تغييرات غير قابل للتعديل العادي، وحماية مفاتيح idempotency، وقواعد الدمج أو رفض التعارض، وربط جميع الردود بهوية الطلب. تُختبر حالات انقطاع الشبكة وquota وتبديل الحساب والتبويبات المتزامنة على متصفحات وأجهزة فعلية، بما فيها سياسة الاحتفاظ بالتغييرات الموجودة في الذاكرة قبل مغادرة الصفحة.

تنشأ نسخ احتياطية واستعادة مجربة وقياسات زمن الفقد والتعافي. لا تعد بيانات المتصفح backup. الترحيل من النسخ القديمة يتم بدفعات معاينة وفحص علاقات ورفض ذري وسجل خطأ لكل صف وحفظ الأصل قابلًا للتصدير. تلزم سياسة حذف واحتفاظ وخصوصية واسترداد بالمؤسسة، وخطة لاسترجاع الأصول والمرفقات وليس جداول السجلات وحدها.

## 6. تكاملات خارجية وموافقة بشرية

يختار المالك مزودي الدفع والتوقيع والبنك والرسائل ومصادر البيانات بعد اختبار أهلية السوق والحقوق والعقود. تشغيل كل مزود انتقال منفصل: إعداد أسرار، sandbox، تحقق webhook/replay، مصالحة أحداث وتسويات، ثم موافقة صريحة على التشغيل الحي. لا يفترض وجود API حكومي أو مصرفي لمجرد وجود عنوان شاشة. اشتراكات المنصة وأموال الإيجارات منفصلة، ولا تُخزن بيانات بطاقات أو تُحاز أموال العميل في النموذج.

## 7. بيئة الاختبار وبوابات القرار

**البوابة الأولى:** تثبيت المتطلبات والسياسات المالية والقانونية والأدوار، وفصل بيئة التطوير والاختبار والإنتاج؛ قاعدة المشروع المُدارة الحالية مشتركة فلا تستخدم لكتابة اختبار على بيانات قائمة.

**البوابة الثانية:** تنفيذ جداول المؤسسة والدفتر والعقود والمستندات والتزامن، ثم اختبارات أمان وعزل ونسخ احتياطي واستعادة ومطابقة مجاميع وإصدار تقارير.

**البوابة الثالثة:** تجربة استخدام فعلية مع مستخدمين معتادين على Excel: إضافة أصل، استيراد ملف، إعداد قالب، إصدار عقد، إصدار فاتورة، تحصيل جزئي، متابعة متأخر، ثم تفسير خطة ورفض فرصة. تقاس الأخطاء وزمن الإنجاز والحاجة للمساعدة، لا الاكتفاء بتقييم شكلي.

**البوابة الرابعة:** تشغيل محدود ببيانات قليلة بعد توقيع الاعتمادات، ومراقبة الأخطاء والمصالحة وتاريخ الحسابات وخطة rollback. لا يبدأ هذا التشغيل أو النشر من تقرير الاختبارات التجريبي وحده.

لم تُحسم الميزانية أو الفريق أو مدد هذه المراحل هنا، ولا يعد تحديدها موافقة على تشغيل خدمات أو قبول مالي أو قانوني. الخطوة التالية المقترحة هي اعتماد سياسات البيانات والدفتر ونموذج المؤسسة، ثم تسعير مراحل التنفيذ على نطاق متفق عليه.
