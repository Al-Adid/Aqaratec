# مراجعة قراءة فقط — توسعة تسويق الوسطاء

**النطاق المراجع:** طلب 26 أكتوبر 2026 فقط، وملفات `client/src/lib/broker-marketing.ts` و`client/src/pages/marketing/BrokerMarketingPage.tsx` و`client/src/pages/marketing/broker-marketing.css` و`client/src/lib/broker-email-drafts.ts`، مع عقود المتطلبات وخطّة المشروع وقائمة المهام والاختبارات المتصلة.

**طريقة المراجعة:** قراءة ثابتة للكود والاختبارات؛ لم تُعدّل ملفات التنفيذ، ولم يُشغّل متصفح أو تُستخدم بيانات مستخدم أو قاعدة بيانات أو Git أو بريد فعلي. لم تُشغّل مجموعة المشروع الكاملة حتى لا تتداخل مع فحوص `check` و`test` و`build` الرئيسية الجارية.

## المانع المؤكد

### ضغط زر «محاكاة الإرسال» يمكنه إنشاء سجلّي محاكاة للحملة نفسها

- **المواضع:** `client/src/pages/marketing/BrokerMarketingPage.tsx:685-694`، و`client/src/lib/broker-marketing.ts:1460-1529`.
- **المثال القابل لإعادة الإنتاج منطقيًا:** بعد حفظ حملة صالحة، يُضغط زر **«محاكاة الإرسال — لم يُرسل بريد»** مرتين سريعًا. كل استدعاء للواجهة ينشئ `requestId` جديدًا عبر `requestId("broker-dispatch-simulation")`. لذلك لا يتطابق مع سجل المحاكاة السابق في فحص التكرار بالمحرك (`dispatchRequestId`)، فينشئ المحرك وثيقة `broker-campaign-dispatch` وتدقيقًا جديدين لكل ضغطة.
- **الأثر:** لا يوجد إرسال شبكي أو بريد فعلي — وهذه الحماية موجودة وصحيحة — لكن الأمر المحلي نفسه غير محمي من النقر المتكرر. يخالف ذلك مطلب منع تكرار أمر الحملة/الضغط، ويترك أكثر من سجل محاكاة لنفس الحملة والمستلمين. كما أن نمط إنشاء طلب جديد لكل ضغطة غير صالح كأساس لأمر إرسال حي لاحق.
- **المعالجة المطلوبة قبل ربط الأمر:** إبقاء مفتاح طلب محاكاة ثابتًا لكل محاولة/حملة حتى تنجح أو تفشل، أو تعطيل الزر أثناء الالتزام ثم حفظ نتيجة المحاكاة، مع اختبار UI يضغطه مرتين ويتحقق من وثيقة محاكاة واحدة فقط. يجب أن يستمر المحرك في إعادة فحص الأهلية والحالة الأحدث عند الالتزام.

## عناصر تحققت ولا تمثل مانعًا في نطاق هذه القراءة

- تاريخ السيناريو يُقرأ من `scenarioDate(state)`، وفروق الأيام مبنية على منتصف الليل UTC. اختبار المحرك يغطي الحدود الشاملة 0 و30 و60 و90 يومًا، ويعامل انتهاء اليوم كـ«قريب الانتهاء» لا كشاغر، مع `availableFrom` في اليوم التالي.
- لا يُعرض العقد النافذ كشاغر: الهدف القريب يتطلب إشغالًا حاليًا وعقدًا نافذًا صحيحًا، ويُستبعد عند وجود عقد لاحق/تجديد أو طلب محجوز/معتمد أو بيانات دورة عقد تالفة.
- حفظ الحملة يعيد تقييم الأهداف والوسطاء على أحدث حالة داخل `commitTransition`، والمحاكاة تعيد التحقق من النطاق والأهداف والمستلمين النشطين قبل إنشاء سجل محلي.
- صلاحيات التعديل مقصورة على دور `operator` في الواجهة والسياق والمحرك؛ أدوار القراءة تستطيع عرض اللقطات فقط. الوسيط الموقوف يبقى في الأرشيف ولا يكون مستلمًا صالحًا.
- سجل الوسطاء يحفظ الحقول المطلوبة، ويتحقق من البريد ومن تكراره دون حساسية لحالة الأحرف، ويحافظ على المعرّف عند التعديل.
- الإيجار التسويقي يبدأ بصفر ولا يرث قيمة الأصل أو إجمالي المبنى؛ لا تُحفظ الحملة قبل إدخال إيجار شهري صحيح موجب وصريح لكل هدف.
- اللقطة المجمدة تحتوي أهدافًا ومستلمين مرجعيين، ولا تضع المستأجر أو الائتمان أو روابط صور خاصة داخل `BrokerCampaignBrief`. مسودة `.eml` لمستلم واحد فقط مع `X-Unsent: 1` ومن دون `From` أو `Cc` أو `Bcc`، والتنزيل Blob محلي.
- محاكاة الإرسال لا تغيّر العقود أو الوحدات أو التحصيل أو الذمم أو النقد؛ تسجل وثيقة محلية بحالة `simulated-not-sent`. تعطيل الإرسال الحي وعدم وجود SMTP أو طلب شبكة مقصودان وصحيحان لأن حساب خدمة البريد لم يُقدَّم.
- حدود النموذج المستخدمة هنا مربوطة بعقد التحقق المشترك: 32 حقل `meta`، و1024 حرفًا للقيمة، و500 سجل لكل نوع، و2000 إجمالًا، و512 KiB للّقطة. يحرس المحرك السعة وحجم اللقطة قبل إعادة النتيجة.
- CSS المراجع يبقي `direction: rtl`، والجداول قابلة للتمرير الأفقي، وتتحول الشبكات والأزرار إلى عمود على الشاشات الصغيرة؛ لا حاجة لإعادة تصميم في هذا النطاق.

## معالجة متزامنة موثقة خارج هذا الحكم

أثناء المراجعة كان جسم الموجز المجمد يساوي نص المقدمة فقط، رغم أن الأهداف المجمدة منظمة. أفاد المنفذ الرئيسي بأنه يعالج ذلك بتوليد جسم عربي مجمد من بيانات الهدف المسموح بها، وجعل المقدمة اختيارية، وإضافة تغطية نص `.eml`. لذلك لم يُسجل هنا كعيب مستقل مكرر؛ يلزم إدراج اختباره ضمن نتائج التنفيذ النهائية.

## الفحوص والحـدود

أُبلغت المراجعة بأن اختبارات الواجهة المتصلة عددها **2**، والمحرك **15**، ومسودات البريد **4**، وجميعها ناجحة. أما `check` و`test` و`build` الرئيسة فكانت قيد التشغيل وقت المراجعة ولم أعد تشغيلها. لم تُراجع الأقسام الأخرى من المشروع أو التصميم العام أو النشر أو تكامل بريد حي.

## متابعة المنفذ الرئيسي بعد المراجعة

أغلق عيب النقر المكرر بمفتاح محاكاة ثابت لكل حملة في الواجهة، وثبت باختبار الضغط مرتين مع سجل واحد. نص الموجز الآن يولد من بيانات الهدف المجمدة ويظهر داخل EML بعد فك ترميزه. النافذة المعلنة في اختبار القراءة تمرر عند إنشاء الحملة، لا تتجاوز حارس أهلية الهدف. اختبارات الأجزاء المتأثرة: 23 ناجحًا؛ الأنواع والبناء ناجحان. لا بريد فعلي ولا اختبار بيانات مستخدم أو نشر في هذه الجولة.
