# إصلاح فتح تفاصيل العقار المحفوظ

## السبب المثبت

في الإصدار المنشور d661a34 كان رابط عقار صوري جديد UUID محفوظ ضمن مجمع 36 وحدة يتحول إلى /404 رغم وجوده في سجل العقارات والتخزين المحلي. طلب HTTP للمسار نفسه يعيد 200 وقالب التطبيق الصحيح، لذلك ليست المشكلة في قبول المسار على الخادم أو رفض UUID. فرضية المراجعة الأولية عن سياسة الخادم لم تثبت وتناقضت مع اختبار HTTP؛ لم نغير المسارات بناء عليها.

WorkspaceIdentityBoundary ينشئ مراقب auth.me عند تركيبه بعد بوابة الدخول. إعادة الجلب الأولية قد تعطيه هوية pending قبل أول نتيجة موثوقة له، فينشئ السياق الحالة الصورية دون قراءة مساحة شخصية. كانت صفحات السجلات تُركب فوق هذه الحالة رغم عدم جاهزيتها: تجد العقارات الصورية الأصلية، لكن لا تجد عقار المستخدم الجديد، فيركب NotFound ويعيد توجيهًا كاملاً غير قابل للاستعادة. يُثبت اختبار انحدار فاشل قبل الحراسة أن صفحة السجل تركبت أثناء isFetching الأولي.

## التصحيح

تُركب صفحات السجلات فقط إذا كانت الهوية غير pending؛ الحالة الأولية المعلقة تعرض رسالة انتظار أو فشل تحقق مع إعادة المحاولة. لم يُعطل الاستعلام ولم تُختلق هوية أو جلسة ضيف. يبقى الاختيار الصريح للضيف ثابتًا، وتبقى النسخة المركبة سابقًا في الذاكرة أثناء إعادة التحقق الخلفي مع حراسة العرض/التعديل القائمة. لا تغيير لبيانات العقار أو الوحدات أو الصور أو العقود أو الذمم؛ ولا تغييرات على نموذج التفاصيل أو API أو مسار /404 للسجلات المفقودة فعلاً.

## الأدلة

- اختبار قبل الحراسة: فشل لنداء Harness أثناء أول isFetching.
- بعد الحراسة: 38 اختبارًا للهوية وبوابة الدخول والتفاصيل ناجحًا.
- اختبار جديد باستعلامات tRPC/React Query حقيقية وHTTP وهمي مؤجل، ومخزن ضيف معزول مكتوب كتابة محروسة: لا تركيب لـNotFound أثناء التحقق الأولي؛ بعد التحقق يعرض عقار villa_complex المحفوظ و36 صف وحدة.
- الفحص العام النهائي: 112 ملف اختبار، 714 ناجحًا واختبار واحد متخطى. pnpm check وpnpm build وgit diff --check ناجحة؛ تحذير حجم chunks غير مانع.
- متصفح المعاينة: فتح رابط المجمع الصوري المحفوظ مباشرة، وبقي المسار UUID نفسه، وعرض عنوان العقار بارتفاع مرئي 43.5 و36 صف وحدة وزر إكمال بيانات الوحدات؛ لا 404. لا إدخال أو حذف بيانات إنتاج.

## التسليم

الإصلاح محفوظ ومعد للنشر المستهدف لإصلاح النسخة العامة المبلغ عنها. نجاح المعاينة والبناء لا يمثل نجاح نشر؛ النشر يُؤكد بنتيجة منصته ثم يعاد اختبار الرابط العام على المخزن الصوري الموجود دون إعادة إنشاء العقار.
